# Local AI Platform - Approach 2: Helm

CPU-only local chatbot and RAG on Kubernetes (k3s), deployed with one Helm chart.
LibreChat is the chat UI. No custom frontend or backend.

## Architecture

Namespace: `local-ai`

    User -> Traefik (HTTPS) -> LibreChat (:3080) -> llm-chat (:8080, llama.cpp)
    LibreChat -> MongoDB (:27017)                  users and conversations
    LibreChat -> rag-api (:8000) -> llm-embed (:8080) -> PostgreSQL + pgvector (:5432)

| Component | Source in this chart |
|---|---|
| LibreChat | Official chart `librechat` 2.0.14 (dependency), image `v0.8.8-rc4` (release candidate) |
| MongoDB | Subchart bundled with the LibreChat chart (`bitnamilegacy` image, no longer maintained), 10Gi |
| PostgreSQL + pgvector | Own templates, `pgvector/pgvector:pg16`, StatefulSet, 30Gi |
| llm-chat, llm-embed | Own templates, one loop over `values.llm` (llama.cpp server) |
| rag-api | Own templates, LibreChat RAG API (lite image) |
| TLS | Own template, self-signed certificate reused on upgrades |
| Ingress | The LibreChat chart's own Ingress, class `traefik` |

Models: Qwen2.5-1.5B-Instruct Q4_K_M (chat), nomic-embed-text-v1.5 Q4_K_M (embeddings).
Meilisearch is disabled. Ollama, vLLM and GPU components are excluded.

## Requirements

- A VM with k3s (bundled Traefik), `helm` and `kubectl`
- Tested on 4 CPU cores, 7.7 GiB RAM, no GPU
- Ports 80 and 443 open to the VM

## Repository layout

    helm/local-ai/
      Chart.yaml                 LibreChat dependency (condition librechat.enabled)
      values.yaml                base values
      values-embed.yaml          enables llm-embed and the embedding model
      values-rag.yaml            rag-api image, embeddings URL, extra env
      values-librechat.yaml      librechat.yaml content, env, resources
      values-https.yaml          hostname, TLS, ingress (contains the VM IP address)
      templates/
        postgresql/              configmap, secret, service, statefulset
        llm/                     deployment, service, pvc (loop over chat and embed)
        rag-api/                 deployment and service
        tls-secret.yaml          self-signed certificate
        librechat-secret.yaml    CREDS_KEY, CREDS_IV, JWT secrets
    docs/                        snapshots and notes

## Install

All overlays are required on every install and upgrade. An omitted overlay turns its
components off again.

1. Choose a hostname. sslip.io gives free wildcard DNS for an IP address:

        export VM_IP=$(curl -s ifconfig.me)
        export HOST="chat.$(echo $VM_IP | tr . -).sslip.io"

   Put `$HOST` into `helm/local-ai/values-https.yaml` (`tls.host`, `DOMAIN_CLIENT`,
   `DOMAIN_SERVER` and the ingress host). If the repository is public, keep the real
   address out of git.

2. Install:

        cd helm/local-ai
        helm dependency update
        helm upgrade --install local-ai . --namespace local-ai --create-namespace \
          -f values-embed.yaml -f values-rag.yaml -f values-librechat.yaml -f values-https.yaml \
          --wait --timeout 15m

3. Check:

        kubectl -n local-ai get pods,svc,pvc,ingress

   Open `https://<HOST>` and accept the self-signed certificate warning.

Secrets (PostgreSQL password, LibreChat `CREDS_KEY`, `CREDS_IV` and JWT secrets) are
generated by Helm on first install and reused on upgrades through `lookup`. Nothing
secret is stored in git. Note that `helm template` shows random values because `lookup`
only works against a live cluster.

## Using the RAG path

Plain chat on a custom endpoint never calls the RAG API. For File Search:

1. Open the Agent Builder in LibreChat.
2. Create an agent with the Local llama.cpp endpoint, model `local-chat`, and File Search enabled.
3. Upload documents in the File Search section of the agent, then chat with that agent.

Files attached in plain chat are delivered to the model as text (the `fileConfig` override
in `values-librechat.yaml`). That only suits short files: extracted text is capped at
1,000,000 characters per turn, and the chat model's context is 4096 tokens.

## Uninstall

    helm -n local-ai uninstall local-ai
    kubectl -n local-ai delete pvc --all
    kubectl delete namespace local-ai

The model PVCs carry `helm.sh/resource-policy: keep`, so they survive `helm uninstall`
and the models are not downloaded again. The PostgreSQL PVC is not deleted by Helm either.
